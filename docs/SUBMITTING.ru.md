# Как добавить карточку в проверенный каталог

Это руководство ведёт от «карточка работает» до принятого пулл-реквеста,
который добавляет её — или её новую версию — в [`verified.json`](../verified.json).
English version: [SUBMITTING.md](SUBMITTING.md).

Коротко:

1. Опубликуйте карточку в **публичном** репозитории GitHub, `dist/` —
   в коммите.
2. Убедитесь, что `npx @neurosquad/card-sdk validate` проходит, и выберите
   точный коммит в ветке по умолчанию, который пойдёт на ревью.
3. Сгенерируйте запись: `node scripts/verify.mjs entry <owner>/<repo>[/<папка>] --commit <sha>`.
4. Допишите поля, которые скрипт знать не может, вставьте запись по порядку
   `id`, выполните `npm run format` и `node scripts/verify.mjs --id <ваш id>`.
5. Откройте пулл-реквест с заголовком `Add <id> <version>` по шаблону.

Ниже — каждый шаг подробно.

---

## 1. Перед началом: требования

Карточка должна выполнять всё это. Пункты с пометкой (CI) проверяет CI,
остальные — ревьюер.

| Требование | Зачем |
| --- | --- |
| Репозиторий **публичный**, на github.com (CI) | Пользователи и ревьюеры должны видеть ровно тот код, который ставят. |
| Карточка — в корне репозитория или в одной его папке, `neurosquad-card.json` в корне этой папки (CI) | Эта папка и есть пакет. Её путь — поле `path`. |
| `dist/` (или то, на что указывает `entry`) **закоммичен** (CI) | Приложение не собирает карточки, оно ставит файлы коммита как есть. |
| `npx @neurosquad/card-sdk validate` проходит без ошибок (CI) | Это те же проверки, что делает приложение при установке. |
| Коммит **в ветке по умолчанию** (CI) | Коммит только из форка или боковой ветки приложение тоже отвергает. |
| В пакете нет файлов, похожих на секреты (`.env`, ключи) (CI) | `neurosquad-card pack` их не пропускает, ревью тоже. |
| В папке пакета нет закоммиченного `node_modules/` (CI) | Приложение его поставило бы, а `pack` из SDK пропускает — хеши разойдутся. |
| Исходники, из которых собран `dist/`, лежат в том же репозитории и воспроизводимо собираются по закоммиченному lock-файлу | Ревьюер читает исходники, а не минифицированный бандл. Только минифицированный или обфусцированный код отклоняется. |
| Каждое разрешение действительно нужно и объяснено в `reason` манифеста | Минимум прав. См. [CONTRIBUTING.md](../CONTRIBUTING.md#permissions). |
| Есть лицензия (файл `LICENSE` и `license` в манифесте) | Чтобы было понятно, что можно делать с кодом. |
| Есть README хотя бы с одним скриншотом | Чтобы пользователи (и ревьюеры) видели, что это и как выглядит. |
| В `displayName` и `author.name` нет слов NeuroSquad, official, verified | Так могут называться только карточки самой `glmn-ai`; остальные приложение отвергает. |
| Архив всего репозитория меньше **50 МБ** | Приложение качает tar-архив всего репозитория на этом коммите и отказывается от бо́льших. Видео и тяжёлые ассеты держите вне репозитория карточки. |

Совет: храните текстовые файлы с переводами строк LF (добавьте
`* text=auto eol=lf` в `.gitattributes`). Хеш дерева считается по байтам,
которые отдаёт GitHub; при CRLF-чекауте на Windows хеш, который локально
печатает `pack`, будет отличаться от настоящего (команда `entry` ниже всегда
берёт байты с GitHub).

## 2. Выберите коммит

Запушьте финальную версию в ветку по умолчанию и возьмите sha коммита:

```sh
git checkout main && git pull
git log -1 --format=%H            # например 3f9c2e7d0b1a4c5d6e7f8091a2b3c4d5e6f70812
```

Именно этот коммит проходит ревью, и именно его пользователи ставят как
проверенную версию. Релиз с тегом — хорошо, но запись закрепляет sha, а не тег.

Ещё раз проверьте пакет на этом коммите:

```sh
npx @neurosquad/card-sdk validate          # в папке карточки
npx @neurosquad/card-sdk pack --dry-run    # список файлов и хеш дерева
```

## 3. Сгенерируйте запись

Сделайте форк этого репозитория, склонируйте его и выполните:

```sh
npm ci
node scripts/verify.mjs entry <owner>/<repo>[/<папка>] --commit <sha>
```

Скрипт скачивает ваш репозиторий на этом коммите ровно так, как это делает
приложение, проверяет манифест и печатает черновик записи со всем, что можно
вычислить: `packageId`, `name`, `description`, `version`, `commit`,
`treeHash`, `permissions`, `optionalPermissions`, `networkHosts`, `license`,
`icon`. Хеш дерева, который он печатает, — окончательный (приложение считает
тот же по архиву GitHub).

Нужен доступ к GitHub API: задайте `GITHUB_TOKEN` (для публичных репозиториев
подойдёт любой токен без прав) или войдите через `gh auth login`; без токена
лимит — 60 запросов в час.

## 4. Заполните запись

Полный пример — все поля, включая необязательные:

```json
{
  "id": "test-radar",
  "packageId": "test-radar",
  "name": { "en": "Test Radar", "ru": "Радар тестов" },
  "description": {
    "en": "Runs the test suite in a connected terminal and shows what broke.",
    "ru": "Запускает тесты в подключённом терминале и показывает, что сломалось."
  },
  "author": { "name": "Acme", "github": "acme" },
  "repo": "acme/neurosquad-test-radar",
  "path": "card",
  "version": "1.2.0",
  "commit": "3f9c2e7d0b1a4c5d6e7f8091a2b3c4d5e6f70812",
  "treeHash": "9b1f0c3e5d7a2b4c6e8f0a1b3c5d7e9f1a2b4c6d8e0f1a3b5c7d9e1f2a4b6c8d",
  "permissions": ["agents.read", "terminals.write"],
  "optionalPermissions": ["clipboard.write"],
  "networkHosts": ["api.example.com"],
  "tags": ["testing", "ci"],
  "category": "dev-tools",
  "license": "MIT",
  "homepage": "https://github.com/acme/neurosquad-test-radar",
  "icon": "icon.png",
  "screenshots": ["docs/screenshot.png"],
  "minAppVersion": "0.1.123",
  "official": false,
  "verifiedAt": "2026-10-01",
  "reviewer": "glmn-ai",
  "notes": "Runs only the command set in its settings; no network besides api.example.com."
}
```

(Манифест этого примера объявляет `network` для `api.example.com`, поэтому
в записи есть `networkHosts`.)

| Поле | Обязательно | Что писать |
| --- | --- | --- |
| `id` | да | Слаг в каталоге, `[a-z0-9-]{2,64}`, уникален в файле. Обычно совпадает с `packageId`; если занят — добавьте префикс (`acme-test-radar`). Между версиями не меняется. |
| `packageId` | да | Поле `name` вашего `neurosquad-card.json`. CI сверяет. |
| `name` | да | Отображаемое имя, `en` обязателен, `ru`/`zh` — по желанию, ≤ 80 символов. Обычно `displayName` манифеста. |
| `description` | да | Одно-два предложения, `en` обязателен, ≤ 300 символов. |
| `author.name` | да | Как вас подписать. Не «NeuroSquad», «official», «verified». |
| `author.github` | да | Ваш логин GitHub (или организации). Должен владеть `repo`. |
| `repo` | да | `owner/repo` на github.com, точно как пишет GitHub (переименованный репозиторий не пройдёт). |
| `path` | нет | Папка карточки внутри репозитория, без слеша в начале и в конце. Не указывать, если карточка в корне. |
| `version` | да | `version` манифеста на `commit`. CI сверяет. |
| `commit` | да | Полный 40-символьный sha из шага 2. |
| `treeHash` | да | Из команды `entry` (или `pack --dry-run` на LF-чекауте). CI пересчитывает. |
| `permissions` | да | Обязательные разрешения манифеста, по алфавиту. `[]`, если их нет. CI сверяет. |
| `optionalPermissions` | если в манифесте они есть | Разрешения с `"optional": true`, по алфавиту. CI сверяет. |
| `networkHosts` | если манифест объявляет `network` | Все хосты разрешения `network`, по алфавиту. CI сверяет. |
| `tags` | нет | До 10 слов в нижнем регистре (`[a-z0-9-]`) для поиска. |
| `category` | да | Одно из `agents`, `productivity`, `dev-tools`, `data`, `integrations`, `fun`, `other`. |
| `license` | да | Идентификатор SPDX; должен совпадать с `license` манифеста, если он там есть. |
| `homepage` | нет | Страница карточки по `https://` — обычно репозиторий или папка. |
| `icon` | нет | Путь внутри папки пакета к квадратному PNG/WebP (обычно `icon` манифеста). |
| `screenshots` | нет | До 8 путей внутри папки пакета (png, webp, jpg, gif). |
| `minAppVersion` | если есть в манифесте | Минимальная версия NeuroSquad; не ниже `minAppVersion` манифеста. |
| `official` | да | `false` для карточек сообщества. `true` — только у репозиториев `glmn-ai`. |
| `verifiedAt` | да | Сегодняшняя дата (`YYYY-MM-DD`); при слиянии ревьюер её обновит. |
| `reviewer` | да | Пишите `glmn-ai`; ревьюер заменит на свой логин. |
| `notes` | нет | Что стоит знать ревьюеру (зачем разрешение, что за сетевой хост). Видно ревьюерам, может показываться пользователям. |

## 5. Вставьте запись в нужное место

- `cards` отсортирован по `id` (обычный строковый порядок). Ставьте запись
  по алфавиту, а не в конец.
- Верхнее `updatedAt` — текущее время в UTC, например `2026-10-01T12:00:00Z`
  (не раньше любого `verifiedAt`).
- Форматирование (JSON с отступом 2, канонический порядок ключей,
  сортировка карточек, перевод строки в конце) сделает скрипт:

```sh
npm run format
```

## 6. Запустите проверки локально

```sh
node scripts/verify.mjs --id test-radar            # ваша запись целиком
node scripts/verify.mjs --changed-only origin/main # ровно то, что CI запустит на PR
node scripts/verify.mjs --offline                  # только проверки файла, без сети
```

Успешный прогон заканчивается строкой `✔ verified.json is valid`.
Предупреждения (`▲`) CI не роняют, но ревьюер о них спросит.

## 7. Откройте пулл-реквест

- **Одна карточка — один пулл-реквест.** Больше ничего в файле не меняйте.
- **Заголовок:** `Add <id> <version>` для новой карточки,
  `Update <id> <старая> → <новая>` для новой версии, `Remove <id>` для удаления.
- **Описание:** шаблон подставится сам — дайте ссылки на репозиторий и
  коммит, опишите, что делает карточка, обоснуйте каждое разрешение и
  сетевой хост, приложите скриншот и отметьте чек-лист.
- Разрешите правки мейнтейнерам (Allow edits from maintainers), чтобы
  ревьюер мог поправить `reviewer` и `verifiedAt` без лишнего круга.

## 8. Что проверяет CI и как читать ошибки

Workflow `verify` запускает на вашем PR `node scripts/verify.mjs --changed-only <base>`.
Каждая ошибка — строка с `✖` (и аннотация в PR):

| Сообщение | Что значит и как исправить |
| --- | --- |
| `must match pattern …`, `must have required property …` | Запись нарушает [схему](../verified.schema.json). Сверьтесь с таблицей полей выше. |
| `must be sorted by id` / `not in canonical form` | Выполните `npm run format` и закоммитьте. |
| `duplicate id` / `the same package as …` | Такой id или такая папка репозитория уже есть. Обновите существующую запись. |
| `repository … not found` | Неверный `owner/repo` или репозиторий приватный. |
| `… now answers as … (renamed or transferred)` | Укажите текущее `owner/repo`. |
| `… is private` | Сделайте репозиторий публичным. |
| `commit … does not exist` | Опечатка в sha или коммит не запушен. |
| `commit … is not reachable from main` | Коммит в другой ветке или только в форке. Влейте его в ветку по умолчанию. |
| `treeHash is X at this commit, the entry says Y` | Хеш посчитан на другом коммите или на CRLF-чекауте. Возьмите `treeHash` из команды `entry`. |
| `packageId …` / `version …` / `permissions: the manifest requires …` | Запись не описывает манифест на этом коммите. Скопируйте значения из команды `entry`. |
| `no files under "…"` / `neurosquad-card.json is missing` | Неверный `path`. |
| `validate …: …` | Карточка не проходит валидатор SDK — приложение её тоже отвергнет. Исправьте, запушьте, возьмите новый коммит. |
| `neurosquad-card pack refused the package: … credentials` | Уберите `.env` и ключи из папки пакета. |
| `pack computes … for the same files` | В папке пакета закоммичены `node_modules/` или `.git`. Уберите их из git. |
| `only official cards may call themselves NeuroSquad …` | Переименуйте `displayName` / `author.name`. |
| `the repository archive is … bytes` | Весь репозиторий на этом коммите больше 50 МБ. Вынесите крупные файлы. |
| `GitHub rate limit reached` | Локально — задайте `GITHUB_TOKEN`. В CI — перезапустите позже. |

## 9. Ревью

Когда CI зелёный, ревьюер NeuroSquad:

- читает исходники на закреплённом коммите (для новой карточки — целиком,
  для обновления — дифф от прошлого проверенного коммита) и сверяет с ними
  `dist/` (может пересобрать);
- проверяет, что каждое разрешение и сетевой хост нужны и объяснены, а
  секреты и данные пользователя не уходят туда, куда не должны;
- ставит карточку с закреплённого коммита и пробует её;
- заполняет `reviewer` и `verifiedAt` и вливает PR.

Первый ответ — в течение **7 дней**; новая карточка обычно проходит за одну-две
недели, небольшое обновление — за несколько дней. Большие карточки, широкие
разрешения (`agents.prompt`, `terminals.write`, `fs.write`, `network.local`) и
много сетевых хостов — дольше.

## 10. Обновление карточки до новой версии

Приложение закрепляет проверенный коммит; новой версии нужно новое ревью:

1. Запушьте новую версию в ветку по умолчанию (поднимите `version` в манифесте).
2. `node scripts/verify.mjs entry <owner>/<repo>[/<папка>] --commit <новый sha>`.
3. В существующей записи замените `version`, `commit`, `treeHash` и — если
   изменились — `permissions`, `optionalPermissions`, `networkHosts`,
   `minAppVersion`, `name`, `description`, `screenshots`. `id` не меняйте.
4. Обновите `updatedAt`, `npm run format`, прогоните проверки и откройте
   `Update <id> <старая> → <новая>`. Опишите, что изменилось, и отдельно
   назовите новые разрешения и хосты — ревьюер смотрит на них первыми.

## 11. Частые причины отказа

- Нет исходников для `dist/` или `dist/` им не соответствует; минифицированный
  или обфусцированный код без читаемых исходников.
- Разрешения, которые карточка не использует или берёт «на всякий случай»
  (`network` на широкий список хостов, `fs.write`, `agents.prompt` у карточки,
  которая только показывает данные).
- Отправка содержимого воркспейса, вывода агентов или настроек на сервер без
  явного объяснения в README и в `reason` разрешения.
- Загрузка кода во время работы (скрипты, iframe, `eval` скачанного текста) —
  работать должен ровно тот код, который проверен.
- Выдача себя за NeuroSquad, другую карточку или другого автора.
- Карточка не работает, это заглушка, или она без явной разницы повторяет
  существующую.
- Нет лицензии, или лицензия запрещает пользователям её запускать.
- Трекинг или аналитика без явного согласия.
